## 2026-06-07 - Implementation Session

### Goal

Implement the approved `beta-access-control` feature with Auth.js email magic-link sign-in, Resend email delivery, Postgres database persistence via Drizzle, beta/admin allowlists, route-level access control, and feedback persistence foundation.

### Starting point

- Repository with planning documentation complete
- No Auth.js or database setup implemented
- Tests and acceptance criteria from plan

### Implementation summary

#### Dependencies installed

- `next-auth` v4.24.14 (next-auth for Next.js email authentication)
- `@auth/drizzle-adapter` (Auth.js adapter for Drizzle ORM)
- `drizzle-orm`, `drizzle-kit` (Drizzle ORM for database abstraction)
- `postgres` (Postgres driver compatible with serverless environments)
- `resend` (Email delivery provider)
- `nodemailer` (underlying email infrastructure for Auth.js Email provider)

#### Database schema and configuration

- Created `lib/db/schema.ts` with Auth.js required tables: `accounts`, `sessions`, `users`, `verificationTokens`
- Added `feedback` table to store: `id`, `userId`, `email`, `resultContext` (JSON), `note`, `createdAt`
- Created `lib/db/index.ts` with lazy-initialized Drizzle client for serverless environments
- Used `postgres` package instead of `pg` for better serverless compatibility

#### Authentication setup

- Created `app/auth.ts` with next-auth v4 configuration
- Configured Email provider with Resend SMTP credentials (`smtp.resend.com:465`)
- Set up JWT-based session strategy with 24-hour magic link expiration
- Configured custom sign-in page at `/auth/signin`

#### Authorization and access control

- Created `lib/auth/allowlist.ts` with:
  - `parseEmailAllowlist()` - parses comma-separated emails from env vars
  - `normalizeEmail()` - normalizes emails for comparison (lowercase, trim)
  - `isBetaAllowed()` - checks if email is in `BETA_ALLOWED_EMAILS`
  - `isAdmin()` - checks if email is in `BETA_ADMIN_EMAILS`
- Created `lib/auth/guards.ts` with route/API protection helpers:
  - `requireBetaAuth()` - page-level guard redirects to signin/denied as appropriate
  - `requireBetaAuthApi()` - API-level guard returns 401/403 status codes
- Applied `requireBetaAuth()` to main page (`/`)
- Protected feedback API endpoints with beta allowlist check

#### User interface

- Created `app/auth/signin/page.tsx` - email magic-link sign-in form with Resend feedback
- Created `app/denied/page.tsx` - access denied page with sign-out option for non-invited users
- Created `app/components/Navbar.tsx` - displays signed-in user email and sign-out button
- Updated `app/layout.tsx` and created `app/providers.tsx` to wrap SessionProvider as client component
- Marked dynamic pages with `export const dynamic = 'force-dynamic'` to avoid prerender issues

#### Feedback persistence

- Created `lib/repositories/feedbackRepository.ts` with:
  - `createFeedback()` - persists feedback with user/email/resultContext/note/timestamp
  - `getAllFeedback()` - retrieves all feedback (admin use)
  - `getFeedbackByUserId()` - retrieves user's feedback
  - `getFeedbackByEmail()` - retrieves feedback by normalized email
- Created `app/api/feedback/route.ts` - POST to create feedback, GET returns 403 (admin-only)

#### API routes

- Created `app/api/auth/[...nextauth]/route.ts` - Auth.js handler routes
- Configured to use Resend for email delivery through SMTP interface

#### Environment configuration

- Updated `.env.example` with:
  - `DATABASE_URL` - Postgres connection string
  - `AUTH_SECRET` - Auth.js secret (min 32 characters)
  - `AUTH_URL` - deployment URL
  - `RESEND_API_KEY` - Resend API key
  - `EMAIL_FROM` - sender address
  - `BETA_ALLOWED_EMAILS` - comma-separated beta tester emails
  - `BETA_ADMIN_EMAILS` - comma-separated admin emails
- Added placeholder values to `.env.local` for build-time configuration

#### Tests

- Created `tests/lib/auth/allowlist.test.ts`:
  - 16 tests for email parsing, normalization, and allowlist checking
  - All tests PASS
- Created `tests/lib/repositories/feedbackRepository.test.ts`:
  - 6 tests for feedback repository CRUD operations
  - All tests PASS

### Known limitations and open items

- **Database connection**: Uses placeholder DATABASE_URL at build time. Real deployment requires live Postgres connection.
- **Resend SMTP configuration**: Requires valid `RESEND_API_KEY` and domain setup in Resend dashboard.
- **Redirect loop prevention**: Manual testing required to ensure auth/callback/denied/logout routes are properly protected.
- **Middleware not implemented**: Used route-level guards instead of global middleware for next-auth v4 compatibility; can be refactored to middleware in future.
- **Admin UI**: No admin surfaces exist yet; admin checks are in place but not actively used.
- **Manual deployed validation**: Cannot complete until actual database, Resend sender domain, and validation identities are configured.
- **Email template customization**: Default Auth.js email template used; future work can customize branding.

### Risks and mitigations

- **Redirect loops**: Route-level guards check auth status and allowlist before rendering; manually test signin/callback/denied pages to verify.
- **Client-side auth hiding**: UI pages hidden via `requireBetaAuth()` - not client-side hiding; protects against direct URL access.
- **Environment variable differences**: Deployment requires proper `RESEND_API_KEY`, `DATABASE_URL`, and `AUTH_SECRET` configuration in Vercel and production database.
- **Session persistence**: JWT sessions used for speed; database remains required for users/tokens/feedback; test local sign-in flow end-to-end.
